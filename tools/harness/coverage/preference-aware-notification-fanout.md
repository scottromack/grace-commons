## Step 2 — coverage matrix

The pair model has two subscribers, two writers and the clock. The writers are the invocation and the redisposer (a [Redispose] caller, or the gap run calling it as the holder); each takes the pair's Lease lease by try_take with D as duration (answered held while another holder's grant stands, taken otherwise; read as expired once the grant lapses, Lease Sizing 2a/2b; released on return; an invocation take past the bound read as expired, Capability requirement 57), reads the pair's latest disposition event, runs the gate and commits as three separate steps, so the clock can run between them and a lease can lapse. A lapsed writer's only move is to yield. The gap run is a reconcile intent (once the invocation is no longer young) and then, in one of two modes, a repair (a [Redispose] call for a gap principal) or an abandonment. The transport ends a Pending record (delivered, failed, expired); another fanout delivers to the same principal under the per-principal exclusion. The gate is a nondeterministic verdict (deliver, only below the cap; suppress with and without retry eligibility; fail). The model keeps what the journal's reads derive (the pair's operative event, the latest record's status, earlier records still live, the committed delivery count), no history: a property of the state is an invariant over the state, and a property of a step is a name `viol` takes when the step breaks it. The batch model has the invocation, the clock, a foreign holder of a pair (the redisposer abstracted to what the invocation sees), Event Log refusing an append, and the gap run's repeated runs: each run past the young edge takes every gap principal's lease and repairs it, abandons it, or carries it (try_take held, the lease lapsed, [Redispose] refused), recording an at-risk record for a carry once the window has passed; the window passes once a run has ended (Capability requirement 29's arithmetic). Fourteen entries in the pair `.cfg`, six in the batch's.
